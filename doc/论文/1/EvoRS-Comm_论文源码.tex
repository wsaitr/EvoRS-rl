\begin{abstract}
现有遥感视觉语言多智能体系统大多沿用通用 Agent 的文本通信范式：每个 Agent 将局部视觉理解压缩为自然语言，再由其他 Agent 基于文本继续推理。该过程容易丢失空间层次、精确位置与细粒度视觉证据，并且固定工作流会让不必要的专家调用和通信持续累积。本文提出 \ours，一个面向遥感视觉理解的双层协作框架。其内层是单 Agent 的受预算演化搜索，通过 candidate、variation、fitness 与 selection 改进局部感知结果；外层由独立于专家池的 Evolution Controller 根据共享状态动态激活 Visual、Knowledge、Reasoning 与 Verification Expert。系统以任务相关的 Scene--Region--Group--Object 稀疏层次描述组织空间证据，将图像与 latent 二进制保存在 ArtifactStore，只在 Workspace 中保存可追溯句柄；Agent 间不直接调用，而由 Router 按策略选定的范围传递 Text、Structure 或 Hybrid 上下文。进一步地，我们使用带有效动作掩码的集中式强化学习策略优化专家激活、Reasoning 通信模态与终止决策，同时显式计入证据质量、结构质量、Agent/模型/工具调用和通信成本。本文给出与实现一致的问题形式化和实验协议；Phase 0--5 的机制闭环已经实现，但论文级多数据集、多随机种子实验仍属于 Phase 6，故主结果数值仍以 \todo 标记。
\end{abstract}

\section{引言}
遥感图像与普通自然图像的一个重要差异在于其空间组织方式。遥感影像通常覆盖大范围地表区域，包含大量小目标、功能区域与重复结构。近年来的 VRSBench、XLRS-Bench、CHOICE 与 GEOBench-VLM 等 benchmark 已将遥感理解从单一分类扩展到 VQA、grounding、目标计数、空间关系、超高分辨率理解与时序分析等任务~\cite{vrsbench,xlrs,choice,geobench}。然而，现有多 Agent 视觉推理仍主要通过自然语言串联：一个 Agent 观察图像后输出文本，另一个 Agent 再从文本恢复语义与空间线索。

这种通信方式存在两个问题。第一，文本会将原本二维、层次化的视觉证据序列化。例如 ``图中存在五架飞机'' 并不能直接告诉接收方五个目标分别位于何处、属于哪个机坪区域、来自哪个 crop、哪些目标仍未验证。第二，图像 latent 与结构关系被压缩为离散 token 后难以无损恢复。最新的 latent agent communication 工作已经指出，纯文本通信会造成信息损失与额外推理开销，并开始直接交换 hidden state 或压缩 latent~\cite{interlat,macf}。但这些方法并未针对遥感场景的显式空间层次设计通信协议。

另一方面，遥感 Scene Graph 已从静态对象关系扩展到层次化和多尺度表示~\cite{knyaz2025,knyaz2026}；SG2 进一步表明多 Agent 可以对 scene graph 进行按需查询~\cite{sg2}。但这些工作主要将图视为视觉表示或检索对象，而不是一种可增量写入、可按范围披露且与视觉制品分离的\textbf{共享协作状态}。本文关注的问题因此不是 ``能否为每张图生成完整 scene graph''，而是：

\begin{quote}\small
\textbf{能否把任务相关的遥感空间层次变成可追溯通信协议，并让一个集中式策略学习何时激活哪个专家、披露何种上下文以及何时停止？}
\end{quote}

我们提出 \ours。其核心不是单独增加一个树结构，也不是让 Agent 发明新语言，而是把协作控制变成结构化决策：
\begin{equation}
 a_t^{\mathrm{ctrl}}=(u_t,c_t),
 \label{eq:commaction}
\end{equation}
其中 $u_t$ 为 Dispatch/Finish/Abort 控制动作，Dispatch 指定目标 Expert；$c_t$ 为 ContextSpec，约束可见的节点、证据句柄、空间层级与 Text/Structure/Latent 模态。当前实现由策略直接选择七种安全动作，Router 再依据 $c_t$ 物化最小披露消息。``演化''在本文中专指单 Agent 内部真实存在的候选变异与选择；多 Agent 间的机制称为\textbf{动态协作（dynamic collaboration）}，避免将普通路由误称为演化算法。

\paragraph{本文贡献。}
\begin{enumerate}
    \item \textbf{双层自然演化协作框架。} 在专家内部实现候选生成、变异、适应度评价和选择，在专家之间使用独立 Evolution Controller 动态决定激活路径；两层通过版本化 Workspace 相连但不混淆职责。
    \item \textbf{遥感层次化多模态通信。} 用任务相关的 Scene--Region--Group--Object 描述保存空间地址，将 Text、Structure 与节点绑定的 Visual Latent 作为互补载荷；大体积二进制保存在 ArtifactStore，Workspace 只记录校验和、兼容消费者和来源句柄。
    \item \textbf{基于强化学习的集中式动态协作。} 构造带状态相关动作掩码的 LearnedRoutingPolicy，在冻结 Cognitive Expert 的条件下学习 Agent 激活、Reasoning 上下文模态和终止行为，并联合优化任务、证据、结构与真实执行成本。
    \item \textbf{可审计的系统实现与实验协议。} 给出动作先于环境转移、标签隔离、专家冻结、轨迹回放与 checkpoint 校验机制，并规划覆盖 VRSBench、CHOICE、XLRS-Bench 与 GEOBench-VLM 的 Phase 6 评测；在该评测完成前不声明论文级性能优势。
\end{enumerate}

\section{相关工作}
\subsection{遥感层次场景表示}
Knyaz 等研究了航拍图的层次 scene graph 与向量化，将对象关系与层级纳入遥感场景理解~\cite{knyaz2025}；后续工作进一步研究多尺度 scene graph generation~\cite{knyaz2026}。这些工作证明了 ``Scene--Region--Object'' 结构对于遥感视觉具有合理性，但主要目标仍是构建或评估 scene graph，而非将其变成多 Agent 的通信协议。本文不主张层次 scene graph 本身的新颖性，而是将其改造成可被 Agent 读写、按层级传递、挂接 visual latent 的共享通信状态。

\subsection{Scene Graph 与多 Agent 推理}
SG2 将 Reasoner 与 Retriever 分离，使多个 LLM Agent 通过 schema-guided query 从 scene graph 中迭代取数，避免一次注入完整图~\cite{sg2}。SaGe 则将 scene graph thinking 用于多模态结构化推理，并进一步采用 graph-aware post-training~\cite{sage}。与之不同，我们关注的是通信本身：结构树不仅是被查询的数据源，而是 Agent 消息的显式载体；同时，视觉 latent 与自然语言和结构节点一起进入 communication action space。

\subsection{多 Agent 强化学习与 latent communication}
MAGRPO 将 LLM collaboration 建模为 cooperative MARL，并通过 multi-agent group-relative policy optimization 联合优化多 Agent 策略~\cite{magrpo}。该路线适合未来的 token-level 多策略联合训练，但本文当前可复验实现选择更清晰的边界：冻结各 Expert，只训练一个位于控制层的小型结构化路由策略，因此不将其包装为 MAGRPO 的变体。与此同时，Interlat 已验证 Agent 可以直接交换连续 hidden states，并报告了显著的推理加速潜力~\cite{interlat}；MACF 在长视频理解中使用 compact latent tokens 支持多 Agent 协作~\cite{macf}。我们的重点是将 latent 明确绑定到任务相关的空间节点及其 bbox/region，并通过句柄和 compatible-consumer 约束使连续表示可定位、可追溯且不会被所有 Agent 默认读取。

\section{问题定义}
给定遥感图像 $I$ 与问题 $q$，系统包含按认知能力划分的 Expert 集合
\begin{equation}
\agentset=\{A_{vis},A_{know},A_{reason},A_{verify}\},
\end{equation}
分别表示 Visual、Knowledge、Reasoning 与 Verification Expert。Evolution Controller $C_\theta$ 属于控制层而不属于 $\agentset$；Expert 不能直接调用另一个 Expert，也不能自行决定下一跳。

系统将持久协作内容维护为版本化 Workspace $W_t$，其中包含 TaskContext、Evidence、Claim/AnswerCandidate、任务相关的 SpatialNode 和 Artifact 句柄。消息、执行轨迹与成本分别由 Inbox、transition log 和 CostVector 管理，而不是把所有文本和二进制堆入 Workspace。控制器实际观察为
\begin{equation}
S_t=(\mathrm{summary}(W_t),H_t,C_t,B_t),
\end{equation}
其中 $H_t$ 是已执行 Expert 路径，$C_t$ 是累计 Agent、Tool、Model 与通信成本，$B_t$ 是剩余预算。Controller 不直接看图或读取 latent 值，只消费紧凑、可序列化且不含 reference answer 的摘要。目标是在任务正确率、证据质量与真实协作成本之间取得权衡。

``自然演化''发生在单个 Agent 的私有循环中。以 Visual Expert 为例，它从初始感知方案产生候选，对尺度、ROI 或答案进行 variation，依据视觉证据、空间一致性、latent 一致性与成本计算 fitness，再选择下一代；未被选中的候选不写入 Workspace。外层只做动态协作：Controller 可以针对计数任务选择 Visual--Reasoning--Verification，而对需要领域语义的分类任务加入 Knowledge，系统不要求每题启动所有 Expert。

\subsection{任务相关的层次化空间描述}
我们使用以下四级语义词汇描述空间层次：
\begin{equation}
\tree_t: \mathrm{Scene}\rightarrow\mathrm{Region}\rightarrow\mathrm{Group}\rightarrow\mathrm{Object}.
\end{equation}
该表达是允许稀疏实例化的层次契约，而不是要求单张图片先构建完整世界模型：与问题无关或无法可靠确定的中间层可以缺省。每个已实例化节点 $v_i$ 定义为
\begin{equation}
 v_i=(id_i,\ell_i,s_i,b_i,c_i,u_i,z_i,p_i),
 \label{eq:node}
\end{equation}
其中 $\ell_i$ 为层级，$s_i$ 为语义标签，$b_i$ 为 bbox/polygon，$c_i$ 为 confidence，$u_i$ 为 uncertainty，$h_i$ 为可选 visual artifact handle，$p_i$ 为 evidence provenance。真实 latent $z_i$ 不直接进入可 JSON 序列化的 Workspace，而存入 ArtifactStore，并由 $h_i$ 记录 SHA-256、shape、dtype、encoder、ROI 与 compatible consumers。一个机场场景可表示为
\[
\mathrm{Airport}\rightarrow\mathrm{Apron}\rightarrow\mathrm{AircraftGroup}\rightarrow\mathrm{Aircraft}_k.
\]
与自然语言相比，该状态显式保留 ``谁属于谁'' 以及 ``目标在哪里''，因此接收 Agent 可以直接使用 $b_i$ 调用 crop/zoom/detector 等视觉工具。

\subsection{层次化多模态通信协议}
传统 Agent 消息通常只有文本 $M^{text}$。我们将消息扩展为
\begin{equation}
M_{i\rightarrow j}=\big(M^{text},M^{struct},M^{latent}\big),
\label{eq:message}
\end{equation}
但每次通信无需发送全部三种模态，而是由策略按需选择。

\paragraph{Text channel.} 用于自然语言推理、任务意图和高层解释。例如 ``当前区域可能为机场，但需要验证机坪中的小目标''。

\paragraph{Structured channel.} 直接发送一个节点、路径或子树，例如
\[
\{\mathrm{Apron},\mathrm{AircraftGroup},b_{ROI},c,u\}.
\]
结构消息承担\textbf{空间地址与语义骨架}功能，下游 Agent 不必从文本重新恢复 bbox 与层次关系。

\paragraph{Visual latent channel.} 对某个节点对应区域 $I[b_i]$，当前实现从与本地 Qwen VLM 对应的视觉塔提取并池化表示
\begin{equation}
 z_i=\mathrm{Norm}\!\left(\mathrm{MeanPool}(E_{vis}(I[b_i]))\right)\in\mathbb{R}^{d},
 \label{eq:latent}
\end{equation}
其中 $d=5120$，向量以 float32 little-endian 制品存储，并用 SHA-256 验证内容。当前同构实现通过受权限约束的 consumer 读取向量，在单 Agent fitness 与多 Agent latent-consumption 诊断中使用其范数和 ROI--Scene cosine；直接 cross-attention 注入和异构投影器属于后续扩展，本文不把它们写成已实现机制。因此层次结构负责 ``这是什么、在哪里''，latent 句柄负责保留可复用视觉内容，text 负责 ``为什么发送它、下一步推理目的是什么''。

\subsection{通信决策空间}
在每个 step，策略从固定、可审计的七动作集合中选择
\begin{align*}
\mathcal U=\{&\mathrm{DispatchVisual},\mathrm{DispatchKnowledge},\\
&\mathrm{DispatchReasoning}_{T+S},\mathrm{DispatchReasoning}_{Hybrid},\\
&\mathrm{DispatchVerification},\mathrm{Finish},\mathrm{Abort}\}.
\end{align*}
其中两个 Reasoning 动作分别披露 Text+Structure 与 Text+Structure+Latent。每个 Dispatch 经 ContextSpec 解码出 payload refs、focus node、spatial level、modalities 和 max items，Router 只物化被授权的记录。该首版动作空间有意保持较小：它真实学习 Expert 激活和关键模态选择，但节点级 payload 仍由确定性上下文构造器选择，不能表述为已经学习任意 payload。状态相关 mask 禁止无视觉证据时推理、无 proposed candidate 时验证、无 verified candidate 时结束，以及无兼容 latent 时选择 Hybrid。

\subsection{集中式动态路由的强化学习优化}
本文当前阶段只训练控制层策略，四个 Cognitive Expert 作为冻结的环境动力学。ControllerObservation 被编码为版本化的 21 维特征 $x_t$，包括任务类型、当前 step、视觉/知识证据、候选状态、兼容 latent、已用 Expert 和累计成本。reference answer 只在 episode 结束后进入环境奖励，不出现在 $x_t$、Workspace 或 Expert observation。策略为带有效动作 mask $M(S_t)$ 的线性 softmax：
\begin{equation}
\pi_\theta(a_t|S_t)=\mathrm{MaskedSoftmax}(Wx_t+b;M(S_t)).
\end{equation}
episode 奖励设计为
\begin{equation}
\begin{aligned}
R={}&R_{task}+\lambda_eR_{evid}+\lambda_sR_{struct}-C_{message}\\
&-C_{agent}-C_{tool}-C_{model}-C_{redundancy}\\
&-C_{invalid}-C_{error}-C_{noncomplete}.
\end{aligned}
\label{eq:reward}
\end{equation}
其中 $R_{task}$ 为最终答案精确匹配奖励；$R_{evid}$ 衡量证据链接与置信度；$R_{struct}$ 衡量稀疏层次的根、父子引用与证据绑定。所有质量项按最终 episode 增量只计算一次，成本来自真实 CostVector 和消息字节，而不是根据计划路径估算。

通信成本按不同模态分别计量：
\begin{equation}
C_{message}=\alpha N_{text}+\beta B_{struct}+\gamma B_{latent},
\end{equation}
其中 $N_{text}$ 是披露的文本 token 数，$B_{struct}$ 和 $B_{latent}$ 是结构化载荷与 latent 的真实字节数。重复调用同一 Expert 另计 $C_{redundancy}$。策略使用按任务类型维护的移动基线 $b_k$，以 $\hat A=R-b_k$ 做 on-policy REINFORCE，并加入熵正则：
\begin{equation}
J(\theta)=\mathbb E_{\tau\sim\pi_\theta}\left[
\hat A\sum_t\log\pi_\theta(a_t|S_t)+\xi\sum_t\mathcal H(\pi_\theta(\cdot|S_t))
\right].
\label{eq:routingpg}
\end{equation}
实现对 logit gradient 做有限幅裁剪，每个 episode 更新后要求参数摘要发生非零变化。该算法是集中式 Controller policy gradient，不是多策略联合更新；若未来把结构化动作序列化为 token 并联合训练 Expert/VLM，可再通过 verl 接入 PPO/GRPO/MAGRPO。

\begin{algorithm}[t]
\caption{LearnedRoutingPolicy 训练流程（简化）}
\label{alg:train}
\begin{algorithmic}[1]
\Require dataset $\mathcal D$, frozen expert pool $\agentset$, routing policy $\pi_\theta$
\For{each training batch $(I,q,y)$}
  \State 初始化 Workspace $W_0$、Inbox、CostVector 与预算 $B_0$
  \For{$t=0,\ldots,T-1$}
    \State 从不含标签的 ControllerObservation 编码 $x_t$ 和 mask $M_t$
    \State 在环境转移前采样 $a_t\sim\pi_\theta(\cdot|x_t,M_t)$
    \State Router 披露 ContextSpec，执行一个 Expert，并验证/提交 WorkspaceDelta
    \State 记录 action id、pre-version、transition、消息和真实成本
    \If{$a_t$ is Finish or Abort} \State \textbf{break} \EndIf
  \EndFor
  \State 在环境侧使用 $y$ 计算式~\eqref{eq:reward}
  \State 用式~\eqref{eq:routingpg}只更新 $\theta$，核验 Expert 指纹不变
\EndFor
\end{algorithmic}
\end{algorithm}

\section{实验设计}
\subsection{Benchmark}
我们计划使用四类互补 benchmark：VRSBench 提供 caption、grounding 与 VQA~\cite{vrsbench}；CHOICE 系统评估遥感 perception/reasoning 能力~\cite{choice}；XLRS-Bench 强调平均约 $8500\times8500$ 的超高分辨率遥感理解~\cite{xlrs}；GEOBench-VLM 覆盖 scene understanding、counting、localization、fine-grained categorization、segmentation 与 temporal analysis~\cite{geobench}。这些 benchmark 的共同点是图像与问题/指令本身即可使用，因此本文方法不假设 CRS、GSD 或传感器元数据必然存在。

\subsection{实现设置}
开发阶段使用同一个本地 Qwen 27B 级 Q4 量化 VLM 服务，不同 Expert 使用独立 prompt；视觉 latent 来自对应的 Qwen 视觉塔。Phase 5 只训练 $7\times21$ 的 Controller 参数，VLM 与 Expert 冻结。Phase 6 将固定模型版本、解码参数、预算与数据划分，使用官方 metric，并至少报告三次随机种子的均值、标准差和配对统计检验。

\subsection{对比方法}
核心对比包含：Direct Single VLM、单 Generalist Agent、Fixed-All-Experts、RuleRoutingPolicy 与 LearnedRoutingPolicy。表示消融比较 Text-only、Text+Structure、Text+Latent 与 Hybrid；内部演化消融移除 variation/selection。若能在相同模型、数据和预算下复现，则再加入 SG2-style graph querying~\cite{sg2}、SaGe~\cite{sage} 和 token-level MAGRPO~\cite{magrpo}，但这些外部路线不作为当前实现完成度的替代证据。

论文必须至少回答以下问题：
\begin{itemize}
    \item \textbf{分层结构是否有效？} 比较 text-only、flat object list、四级树。

\end{itemize}

\subsection{内部演化与协作路径分析}
自然演化不能仅通过最终 accuracy 声明。单 Agent 层需要报告每代 population、variation operator、fitness components、parent/selected candidate 与停止原因；多 Agent 层则报告 Expert 激活矩阵、路径分布、消息模态与层级分布，但将其称为动态协作而非演化。若训练后 counting 任务更多选择 Visual--Reasoning--Verification，而需要领域概念的分类任务更常加入 Knowledge，且在匹配预算下提升任务奖励，才能说明策略形成了任务相关的协作分工。

\section{讨论}
\paragraph{为什么需要结构 + latent，而不是只用 latent？}
latent 能保留丰富视觉信息，但缺乏天然的 ``地址'' 与可解释空间语义；结构树提供 node id、bbox、parent 与层级，使 latent 被明确绑定到某个遥感区域。两者组合可以分别承担索引与内容角色。

\paragraph{为什么需要文本？}
结构适合空间关系，latent 适合保留视觉表征，但复杂推理意图、验证请求与任务解释仍适合语言，因此本文不是 ``去文本化''。当前策略在 Reasoning 的 Text+Structure 与 Hybrid 间选择；更细粒度的三通道组合属于后续动作空间扩展。

\paragraph{异构 Agent 的可行性。}
当前使用共享视觉塔并通过 compatible-consumer 约束读取。若采用不同 VLM，需要解决 latent space alignment；可训练轻量 projection 或共享 bottleneck tokenizer，但这属于后续扩展而非 Phase 0--5 的完成条件。

\paragraph{潜在风险。}
若树结构由错误 detector/VLM 构造，其错误可能在团队中传播，因此 Verifier、uncertainty 与 provenance 机制非常关键。另一个风险是 latent channel 带宽过高，导致 ``准确率提升只是因为传更多信息''；因此 matched-bandwidth 实验是论文必须项。

\section{结论}
本文提出 \ours：单 Agent 在私有循环中执行受预算的 candidate--variation--fitness--selection，多个 Cognitive Expert 则由独立 Evolution Controller 通过版本化 Workspace 和 Router 动态协作。系统用可稀疏实例化的 Scene--Region--Group--Object 描述组织空间证据，以 ArtifactStore 保存图像与 visual latent 二进制，并按 ContextSpec 披露 Text、Structure 或 Hybrid。当前 Phase 5 使用集中式 masked policy gradient 学习 Expert 激活、Reasoning 模态与终止行为，所有动作均可追溯到其发生前的 Workspace version。Phase 0--5 已形成可运行、可回放和可校验的机制闭环；完整 benchmark、多随机种子、消融与成本曲线仍需由 Phase 6 实验填写，因此本文不预设最终性能结论。
